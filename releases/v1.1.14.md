# 뉴스 모니터 v1.1.14

장시간 실행 후 통신 보조 프로세스를 시작할 때 발생할 수 있는 `Failed to start embedded python interpreter!` 오류를 수정했습니다.

- EXE의 Python 압축 해제 위치를 시스템 임시 폴더에서 `%LOCALAPPDATA%\NewsMonitor\runtime\_MEI...`로 변경했습니다. 시스템 임시 폴더 정리로 실행 중인 `base_library.zip`이 사라지는 경로를 피합니다.
- 유휴 후 또는 통신 시간 초과 후 다시 만드는 HTTP 보조 프로세스도 같은 전용 런타임을 사용합니다. 실행별 폴더는 분리되며 정상 종료 시 PyInstaller가 정리합니다.
- 시작 로그에 런타임 위치를 기록하고, 빌드 검증에서 전용 경로 설정을 확인합니다.
- 설정·기사·봇 정보와 자동 업데이트 방식은 유지합니다.

## 검증 방법

`python audit/reproduce_runtime_cleanup.py`는 기존 방식과 수정 방식의 작은 EXE를 만들어 첫 보조 프로세스 종료 후 테스트용 시스템 임시 폴더의 `base_library.zip`만 삭제합니다. 기존 방식의 두 번째 Python 시작 실패와 수정 방식의 정상 재시작을 비교합니다. `python scripts/smoke_exe.py`는 실제 앱 EXE의 한글·공백 경로, HTTP 시간 초과 후 복구, GUI 및 종료 시 런타임 정리를 확인합니다.

실제 사용자 PC에서 파일을 삭제한 프로그램이나 정책은 특정하지 못했습니다. 위 검증은 임시 파일 소실 조건을 재현하며, 실제 며칠간의 연속 실행 검증을 대신하지 않습니다.

로컬 검증 결과: 전체 테스트 304개 통과. 기존 방식은 임시 ZIP 삭제 후 보조 프로세스 종료 코드 1과 동일한 Python 시작 오류를 재현했고, 수정 방식은 종료 코드 0으로 정상 재시작했습니다. 실제 앱 EXE 실행 검사, 업데이트 파일 교체 및 자동 설치 후 재시작 검사도 통과했습니다.

## 설치

자동 업데이트를 지원하는 기존 설치형 앱은 시작 5초 후 또는 실행 중 6시간마다 새 버전을 확인하고, 다운로드·검증 후 작업이 끝나면 자동 설치 및 재시작합니다. 설정의 `업데이트 확인`으로 바로 확인할 수도 있습니다.

수동 설치 시 기존 프로그램을 종료한 뒤 `NewsMonitor-Setup-1.1.14.exe`를 실행하세요. v1.1.10 이하 또는 이전 포터블 빌드는 설치 파일을 한 번 직접 실행해 전환하세요. 기존 설정과 기사는 유지됩니다. 소스 수정만으로 이미 실행 중인 이전 EXE에는 적용되지 않습니다.
