# 뉴스 모니터 v1.1.4

배포일: 2026-10-15 (한국 시간)

v1.1.2 이후 개발한 본문 중복 개선·공유 대기열 초기화·기관별 뉴스 묶음 공유를 모두 포함한 정식 업데이트입니다.

1. **기관별 뉴스 묶음 공유**: 중복 제거와 중요도 선별 후, 전송 시점에 대기 중인 같은 기관의 뉴스를 한 메시지에 모아 보냅니다. 기관명 아래 기사별 제목·언론사·원문 링크를 표시합니다.
2. **기관명·약칭 인식**: 제목의 기관명을 우선 사용하고, 필요하면 같은 사건의 구성 기사와 검색 태그를 참고합니다. 기관을 확인하기 어렵거나 여러 기관이 함께 주제인 기사는 개별 공유합니다.
3. **플랫폼에 맞는 메시지**: 카카오는 개별 원문 링크를 제공하는 리스트로 최대 3건씩, 텔레그램은 메시지 길이에 맞춰 최대 10건씩 공유합니다. 길이 제한에 걸린 기사는 다음 메시지에 남겨 링크와 기사가 누락되지 않도록 합니다.
4. **기사별 공유 이력 유지**: 한 번에 보내는 기사 전체를 같은 트랜잭션에서 전송 중으로 처리하고, 각 기사에 성공·실패·결과 불명을 기록합니다. 결과 불명 묶음은 자동 재전송하지 않으며 명확한 실패·요청 제한에 대한 기존 처리도 유지합니다.
5. **본문 중심 중복 강화**: 제목이 달라도 본문이 거의 같거나 공통 본문 비중이 큰 발췌 기사는 묶습니다. 관련기사·광고·기자 및 발행 정보를 정리하고, ‘2차 피해’와 ‘250명’처럼 의미가 다른 숫자나 발행 날짜 차이로 같은 사건을 분리하지 않습니다. 낮은 본문 점수 때문에 기존 동일 사건 묶음이 풀리는 문제도 개선했습니다.
6. **피해 규모 변경 구분과 즉시 재검사**: ‘183명→250명’처럼 늘어난 피해 규모는 이전 보도와 구분하고, 같은 250명 피해 보도끼리 묶습니다. 기존 판정 캐시를 새 알고리즘으로 재평가하며 본문 묶음이 완성되면 공유 대기열도 바로 재검사합니다.
7. **공유 대기열 초기화**: 카카오 사용자 또는 텔레그램 공유 대상 방의 대기·중요도 제외·실패 기사를 초기화할 수 있습니다. 초기화 시점을 저장해 재시작 후 이전 기사가 다시 등록되지 않도록 하고, 성공·결과 불명 이력과 설정·수집 기사는 유지합니다. 이미 전송 중인 메시지는 취소하지 않습니다.
8. **중요 뉴스 선별과 기존 보호 유지**: 보안 사고·확정 조치·서비스 장애 중심의 중요도 선별, 기관명·약칭 비교, 수신자별 중복 공유 방지, 유료 발송 차단 및 기존 발송 간격을 유지합니다.

전송 대기열에 함께 있는 기사를 묶으며 기존에 보낸 메시지는 수정하지 않습니다. 새로 들어온 뉴스는 다음 전송에서 묶습니다.

## 다운로드 및 적용

- `NewsMonitor.exe`: Windows 실행 파일.
- `NewsMonitor.exe.sha256`: SHA-256 검증 파일.
- `RELEASE_NOTES.md`: 업데이트 안내.
- 기존 사용자는 설정 → `프로그램 / 업데이트` → `업데이트 확인` 후 다운로드가 완료되면 프로그램을 완전히 종료하고 다시 실행하세요.
- EXE 옆의 `data/`를 유지하면 기존 설정·수집 기사·공유 이력을 이어서 사용합니다.

검증: 로컬 회귀 테스트 208개와 패키징된 GUI·본문 비교·기관별 메시지 구성 검증을 통과했습니다. Actions에서도 회귀 테스트, EXE 빌드, 패키징된 실행 및 실제 업데이트 교체·백업·재시작을 검증한 뒤 게시합니다.
