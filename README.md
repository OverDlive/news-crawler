# 키워드 뉴스 모니터

모니터링 PC에 띄워 두는 Windows 데스크톱 GUI 첫 버전입니다.
Python 표준 라이브러리(Tkinter, SQLite)만 사용하므로 추가 패키지나 API 키가 필요하지 않습니다.

## 실행

Python 3.10 이상과 Tkinter가 필요합니다. 이 PC에서는 Python과 Tkinter를 확인했습니다.
Python 설치에 Tcl/Tk 스크립트가 ZIP으로만 포함된 경우, 프로그램 폴더의 `.tk-runtime/`에 해당 기본 런타임을 풀어서 사용합니다.

- **`실행.bat` 더블 클릭**: 실제 뉴스 모니터 실행
- **`데모 실행.bat` 더블 클릭**: 가상 기사로 화면 확인. 실제 기사 저장소와 분리됩니다.
- 터미널: `python app.py`
- 전체 화면으로 실행: `python app.py --fullscreen`

1. `키워드 / 설정`을 엽니다.
2. `발전그룹사 등록` 탭에서 `전력 및 발전 그룹사 일괄 등록` 또는 `텍스트 파일 불러오기`를 누릅니다. 일반 검색은 `키워드 / 검색 조건` 탭에서 입력하고 `추가`를 누릅니다.
3. `저장하고 적용`을 누르면 바로 수집을 시작합니다.
4. 뉴스 카드를 클릭하면 미리보기가 표시됩니다. `기사 열기`는 기본 웹 브라우저에서 RSS가 제공한 기사 링크를 엽니다.
5. F11로 전체 화면을 켜고, Esc로 해제합니다. 좌우 화살표 또는 이전/다음 버튼으로 페이지를 넘깁니다.

## 제공 기능

- 키워드 추가·수정·삭제 및 사용/중지 (최대 20개)
- 한국어 Google 뉴스 RSS 검색, 연결 실패 시 Bing 뉴스 RSS 자동 대체 수집, 자동 갱신, 수동 확인
- 동일 URL 및 언론사가 다른 유사 기사 중복 제거, 여러 키워드에 걸린 기사 통합 표시
- 발행 시각 최신순 정렬, 키워드 필터, 발견 시각 기반 NEW 강조
- 기사 제목·언론사·발행 시각·RSS 설명 및 기사 본문 핵심 요약 미리보기
- 자동 페이지 전환 및 큰 글씨 전체 화면
- 새 결과는 페이지 전환 또는 `새 결과 보기`를 누를 때 반영하여 읽는 중인 카드가 이동하지 않도록 처리
- 미리보기 및 설정 창을 여는 동안 자동 페이지 전환 일시 중지
- 라이트·다크·시스템 테마 선택 및 저장: `키워드 / 설정` → `모니터링 설정` → `화면 테마` → `저장하고 적용`
- 시스템 테마는 Windows의 앱 색 모드를 따라 자동 변경 (설정·미리보기 창을 닫은 뒤 반영)
- 패널·뉴스 카드·미리보기의 16px 모서리, 20px 내부 여백, 12px 섹션 간격을 공통 디자인 토큰으로 관리
- Tab으로 뉴스 카드에 이동하고 Enter 또는 Space로 미리보기 열기
- 수집 실패 시 기존 기사 유지, 오류 표시 및 1분 후 자동 재시도 (서버가 지정한 대기 시간 준수)
- 키워드와 화면 설정, 기사 및 마지막 수집 성공 시각 저장

기본값: 수집 완료 후 10분 검색 간격, 최근 24시간, 화면당 5개, 20초 페이지 전환, 발견 후 10분 NEW 표시.
화면 크기에 따라 표시 개수를 설정값 이하로 조절하고, 카드 설명을 생략하거나 긴 제목 끝을 줄입니다. 전체 제목은 미리보기에서 확인할 수 있습니다.

## 수집과 저장

상세 검색 조건을 지정하지 않은 기존 키워드는 문구 검색으로 전달합니다. 관련성은 뉴스 검색 결과에 따르며, RSS 검색 결과가 모든 기사를 포함한다고 보장하지는 않습니다.
RSS가 제목을 설명으로 반복하거나 본문 요약을 제공하지 않으면 미리보기에서 해당 상태를 안내합니다.
제목과 RSS 설명의 유사도를 비교해 같은 소식은 최신 기사 하나로 통합 표시합니다. 공백·문장부호·속보/종합 표시,
기본 발전그룹사 약칭(한전/한국전력 등), 숫자 표기(2만4천/2만4000 등)를 정규화합니다.
발행 시각이 48시간 이내인 기사끼리 비교하며, 다른 발전그룹사나 서로 다른 수치가 명시된 기사는 분리합니다.
통합된 기사들의 검색 태그와 최초 발견 시각을 유지하고, 미리보기에서 통합 건수와 언론사 목록을 확인할 수 있습니다.
키워드/조회 기간 필터를 먼저 적용하므로 특정 키워드로 보면 그 조건에 맞는 기사 중 대표를 선택합니다.
원본은 삭제하지 않으며 기존 저장 기사에도 표시 시 적용됩니다. RSS 정보만 사용하므로 표현이 크게 다른 중복은 남을 수 있습니다.
기사 원문을 확인해 핵심 문장을 자동 발췌하는 요약을 제공합니다. 생성형 AI 및 알림음은 포함하지 않습니다.

### 기사 내용 확인 및 자동 요약

자동 수집한 기사와 저장된 조회 기간 내 기사에 대해 백그라운드에서 원문을 확인합니다.
언론사가 제공한 구조화 데이터의 `articleBody` 또는 기사 본문 영역에서 텍스트를 추출하고,
제목과 관련 있는 핵심 문장을 최대 3개, 360자 이내로 발췌합니다. 별도 패키지·API 키·요약 이용료가 없습니다.
뉴스 카드에는 요약이 표시되고, 카드를 클릭하면 미리보기에서 요약의 근거와 RSS 설명을 함께 확인할 수 있습니다.
미리보기를 연 상태에서도 요약이 완료되면 내용이 자동 갱신됩니다.

`본문 요약`은 실제 기사 본문을 확인한 결과입니다. 원문 차단, 로그인 요구, 동적 페이지,
지원하지 않는 본문 구조 또는 Google 뉴스의 원문 링크를 확인할 수 없는 경우에는
`RSS 요약`으로 표시합니다. RSS가 제목만 반복하거나 설명이 없으면 요약할 내용이 없다고 안내합니다.
본문을 확인하지 못한 상태에서 제목으로 내용을 만들어내지는 않습니다.
Google 링크에서 원문을 찾을 수 없으면 Bing RSS에서 제목·언론사가 같고 발행 시각이
48시간 이내인 기사 링크를 찾아 본문 확인을 시도합니다. 일치하는 기사가 없으면 RSS 설명으로 처리합니다.
원문에서 발췌한 문장을 사용하므로 자세한 맥락은 `기사 열기`로 확인하세요.

요약은 `news.sqlite3`의 별도 테이블에 저장되어 재시작 후에도 유지됩니다.
본문 요약은 다시 요청하지 않으며 RSS 요약·확인 불가 결과는 24시간 뒤 원문 확인을 재시도합니다.
기사를 삭제하거나 보관 기간이 지나 정리하면 연결된 요약도 삭제됩니다.
원문은 한 번에 한 기사씩 확인하며 요청별 대기 제한은 10초, 응답 크기 제한은 2MB입니다.
기사 전문은 저장하지 않습니다. 데모에서는 외부 원문 확인을 하지 않으며,
기존 카카오 알림은 RSS 설명을 사용하는 동작을 유지합니다.

실제 자료는 프로그램 옆 `data/`에 저장됩니다.

- `settings.json`: 키워드 및 설정
- `news.sqlite3`: 기사, 키워드 연결 및 수집 성공 시각
- `monitor.log`: 오류 기록 (파일당 1MB, 이전 로그 최대 3개)

데모는 `demo_data/`를 사용합니다. 손상된 설정은 원본을 `settings.invalid-*.json`에 보관하고 초기 설정으로 시작합니다.
삭제하거나 이름을 바꾼 키워드의 연결 기록은 제거하며, 다른 키워드와 공유하지 않는 기사도 제거합니다.
사용을 중지한 키워드는 저장된 설정에 남지만 수집/표시에서 제외됩니다. 30일보다 오래된 기사는 정상 수집 후 정리합니다.
저장 위치는 `python app.py --data-dir "원하는 폴더"`로 변경할 수 있습니다.

인터넷 연결이 필요합니다. 데스크톱 수집기는 별도 스레드에서 Google RSS를 한 번에 하나씩 최소 5초 간격으로 요청하며,
요청당 소켓 대기 제한은 12초입니다. 수집·파싱은 작업 스레드가 처리하고 화면과 SQLite 저장은 GUI 스레드에서 처리합니다.
서버별 한 차례 수집은 최대 10분까지 기다립니다. DNS 응답이나 통신이 장시간 멈추면 해당 수집 대기를 종료하고,
Google 실패 시 Bing으로 대체 수집합니다. 뒤늦게 끝난 요청은 기사 저장이나 화면 갱신에 반영하지 않습니다.
화면 갱신 오류가 발생해도 자동 확인 타이머는 계속 실행됩니다. PC 절전 등으로 2분 이상 실행이 멈췄다가
복귀하면 남은 검색 간격과 관계없이 자동 확인하며, 복귀 전 진행하던 수집은 취소하고 새로 확인합니다.
PC가 절전 중일 때는 수집할 수 없으므로 새벽 내내 수집하려면 Windows 전원 설정에서 자동 절전을 해제하세요.
첫 화면은 키워드 등록을 기다립니다. 프로그램이 닫혀 있는 동안에는 수집하지 않습니다.

## 텔레그램 단체방 / 채널 자동 공유

기존 카카오 알림을 유지하면서 텔레그램 방 한 곳에 새 기사의 제목·언론사·RSS 설명·링크를 자동 공유합니다.
프로그램을 다시 실행한 뒤 메인 화면의 `텔레그램 공유`를 사용하세요.

1. 텔레그램 `@BotFather`에서 `/newbot`으로 이 프로그램 전용 봇을 만들고 토큰을 발급받습니다.
2. 봇을 단체방에 초대합니다. 채널은 봇을 관리자로 추가하고 메시지 게시 권한을 줍니다.
3. 프로그램에 **봇 토큰만 입력**하고 `토큰 저장 / 방 찾기`를 누릅니다. 방 ID를 직접 입력할 필요가 없습니다.
4. 방이 보이지 않으면 단체방에서 `/start@봇이름`을 보내거나, 채널에 새 게시물을 올린 뒤 다시 방 찾기를 누릅니다.
5. 목록에서 대상 방을 선택하고 `자동 공유 시작`을 누릅니다. `테스트 보내기`로 연결을 확인할 수 있습니다.

봇 토큰만으로 텔레그램의 모든 참여 방을 조회할 수는 없어, 최근 24시간 이내의 봇 초대·명령·채널 게시물로
방을 찾습니다. 이미 찾은 방은 저장되어 재시작 후에도 유지됩니다. 개인 채팅은 대상 목록에서 제외합니다.
봇 업데이트는 이 프로그램에서 수신하므로 다른 봇 프로그램과 같은 토큰을 공유하지 마세요.
기존 웹훅이 있으면 자동 삭제하지 않고 새 전용 봇을 만들도록 안내합니다.

최초 대상 연결 이후 발견한 기사만 전송하며, 같은 방·기사 URL의 중복을 방지합니다.
다른 방으로 변경하면 연결 시각부터 새 기사만 보냅니다. `공유 중지`는 대기열을 보존하며,
같은 방에서 `자동 공유 시작`으로 재개하면 기존 대기열을 이어서 보냅니다. OFF 동안 새 기사는 대기열에 넣지 않습니다.
발송 간격은 최소 4초이며 텔레그램의 요청 제한 응답에 따라 추가로 대기합니다.
API 성공과 휴대폰의 팝업·소리 알림은 별개이며, 각 사용자의 텔레그램 알림 설정에 따릅니다.

실패하면 자동 공유를 중지합니다. 권한·토큰을 해결하고 `실패건 재시도`와 `자동 공유 시작`으로 재개하세요.
통신 시간 초과·전송 중 종료·응답 이상은 `결과 불명`으로 표시하고 중복 방지를 위해 자동 재전송하지 않습니다.
대상 방에서 실제 수신 여부를 확인하세요. 토큰은 Windows DPAPI로 암호화하여 `data/telegram.sqlite3`에 저장하며,
일반 설정과 로그에는 기록하지 않습니다. 다른 봇 계정으로 교체하면 이전 방 목록과 전송 대기열·내역을 초기화합니다.
같은 봇의 토큰 교체는 대상 방과 내역을 유지합니다. 프로그램 실행 중에만 발송하며 데모는 네트워크 연결·발송을 하지 않습니다.

공식 API: https://core.telegram.org/bots/api

## 카카오톡 사용자별 알림

메인 화면의 `카카오 알림`에서 사용자 이름과 **각 사용자의 액세스 토큰**을 입력하고
`수신 활성화`를 체크한 뒤 `등록 / 수정`을 누릅니다. 등록 이후 발견한 새 기사의
제목·언론사·RSS 설명(합계 최대 200자)과 기사 보기 링크를 해당 토큰 소유자의
`나와의 채팅방`에 자동 전송합니다. 프로그램 실행 중에만 발송하며 데모는 발송하지 않습니다.

카카오디벨로퍼스 앱에서 카카오 로그인을 활성화하고 각 사용자가 `talk_message`
동의항목에 동의하여 발급받은 액세스 토큰이 필요합니다. REST API 키나 관리자 키를
토큰 칸에 입력하지 마세요. 기사 버튼의 URL 도메인은 앱의 `제품 링크 관리 > 웹 도메인`에
등록해야 합니다. Google 뉴스 RSS 링크는 `https://news.google.com`, Bing이 제공하는
언론사 직접 링크는 해당 언론사 도메인을 등록해야 합니다.

같은 사용자 이름을 선택하면 수정할 수 있으며, 토큰을 비워 두면 기존 토큰을 유지합니다.
수신 사용자 목록의 `ON / OFF`를 클릭하거나 사용자를 선택한 뒤 `수신 OFF로 변경` / `수신 ON으로 변경`을
누르면 해당 사용자의 수신 상태가 즉시 저장됩니다. 다른 사용자와 토큰 설정은 유지되며 재시작 후에도 적용됩니다.
OFF인 동안 새 기사 알림을 추가하거나 대기 중인 알림을 전송하지 않습니다. ON으로 바꾸면 기존 대기 알림의 전송을 재개합니다.
토큰은 Windows DPAPI로 암호화해 `data/kakao.sqlite3`에 저장합니다. 이 파일은
암호화한 Windows 계정과 PC에서 사용하세요. 일반 `settings.json`과 로그에는 토큰을 저장하지 않습니다.
액세스 토큰만 등록하면 만료 시 새 토큰을 직접 등록해야 합니다.

등록된 사용자를 선택하고 `즉시 알람 보내기`를 누르면 저장된 설정으로 테스트 메시지
1건을 바로 보냅니다. 새 기사 수신을 켜고 저장한 상태에서 사용하며, 데모에서는 비활성화됩니다.
필요한 토큰 갱신 후 전송하고 성공·실패 원인을 화면과 전송 내역에 표시합니다.
링크는 최근 수집 기사(없으면 `https://news.google.com`)를 사용하므로 해당 웹 도메인이
카카오 앱에 등록되어 있어야 합니다. 전송 중에는 중복 클릭할 수 없습니다.
`API 전송 성공`은 카카오가 `result_code=0`을 반환했다는 뜻이며, 휴대폰에서 실제
메시지를 확인했다는 뜻은 아닙니다. 등록 이름은 관리용이며 수신 계정은 액세스 토큰으로
결정됩니다. 카카오톡의 `나에게 보내기`는 메모 기능이므로 팝업·소리 알림을 제공하지 않습니다.

### 토큰 자동 갱신

사용자를 선택한 뒤 `자동 갱신`을 눌러 다음 값을 입력하고 저장합니다.

- 액세스 토큰을 발급한 앱의 **REST API 키**
- 해당 사용자의 **리프레시 토큰** (`refresh_token`)
- 앱에서 클라이언트 시크릿이 활성화된 경우 **클라이언트 시크릿**

이 값들도 Windows DPAPI로 암호화해 저장합니다. 수정 시 빈칸은 기존 값을 유지합니다.
자동 갱신 체크를 해제하고 저장하면 이 갱신 인증 정보를 삭제합니다.
리프레시 토큰은 카카오 로그인 인가 코드를 토큰으로 교환한 응답에서 확보해야 합니다.
테스트 도구에서 액세스 토큰만 복사했다면 그것만으로 리프레시 토큰을 만들 수 없습니다.
토큰 요청 절차: https://developers.kakao.com/docs/ko/kakaologin/rest-api#request-token

설정 직후 한 번 갱신해 실제 만료 시각을 확인하고, 이후 카카오 응답의 `expires_in`을 기준으로
**만료 10분 전** 갱신합니다. 뉴스가 없어도 실행 중에는 30초 간격으로 갱신 여부를 확인합니다.
재시작해도 만료 시각과 갱신 정보가 유지되어, 만료가 지났다면 시작 후 갱신을 시도합니다.
응답에 새 리프레시 토큰이 있으면 교체하고, 없으면 기존 토큰을 유지합니다.

연결 실패·서버 오류·요청 제한은 5분 후 재시도하며 그동안 해당 사용자의 뉴스는 대기합니다.
갱신 인증 실패는 자동 반복을 멈추고 전송 내역에 원인을 표시합니다. 새 인증 정보를 등록하면 재개됩니다.
리프레시 토큰도 만료되거나 동의가 철회되면 카카오 로그인으로 다시 발급받아 등록해야 합니다.
프로그램이 종료된 동안에는 갱신하지 않습니다. 데모에서는 갱신 API도 호출하지 않습니다.

사용자별·기사 URL별 전송 기록은 재시작 후에도 유지됩니다. 실패하면 해당 사용자의 수신을
자동 중지하고 알림 창에 원인을 표시합니다. 원인을 해결한 뒤 ON으로 저장하고
`선택 실패건 재시도`를 눌러 보류된 실패건을 다시 전송할 수 있습니다.
통신 시간 초과나 전송 중 종료는 실제 전송 여부가 불명확하므로 자동 재전송하지 않습니다.
카카오톡을 확인한 뒤 재시도하세요. 재시도 시 중복될 수 있습니다.
성공한 메시지는 사용자 삭제로 회수되지 않습니다. 수신자는 내용을 복사하거나 전달할 수 있습니다.

공식 문서: https://developers.kakao.com/docs/ko/kakaotalk-message/rest-api

## 발전그룹사 등록

설정을 열면 `발전그룹사 등록` 탭이 먼저 표시됩니다. 첨부 텍스트와 동일한
11개 그룹사의 이름·약칭, 공격 유형 24개, 개인정보위·정부 대응 20개 검색어가 기본 제공됩니다.

- `전력 및 발전 그룹사 일괄 등록`: 선택한 분류를 모든 기본 그룹사에 등록합니다. 반복 등록해도 중복 항목을 만들지 않습니다.
- `텍스트 파일 불러오기`: `[발전그룹사 키워드]`, `[공격 유형]`, `[개인정보위·정부 대응]` 세 구역을 읽습니다. UTF-8과 CP949를 지원합니다. 프로젝트의 `발전그룹사 키워드 예시.txt`를 참고하세요.
- 개별 등록: 그룹사를 목록에서 선택하거나 직접 이름·약칭을 입력하고, 분류를 체크한 뒤 `그룹사 등록 / 수정`을 누릅니다. `저장하고 적용`도 현재 입력을 등록합니다.
- 등록 목록에서 그룹사를 선택해 약칭·분류·제외어·확인 범위를 수정하거나 그룹사 전체를 중지·삭제할 수 있습니다. 그룹사는 최대 40개이며 일반 검색 조건 20개와 별도로 관리합니다.
- 분류 검색어는 `|`, 쉼표 또는 줄바꿈으로 구분합니다. 분류 검색어를 수정하고 저장하면 해당 분류를 사용하는 모든 그룹사에 반영됩니다. `정보 유출`, `KEPCO KPS` 같은 문구 내부 공백은 유지합니다.
- 등록 목록에서 그룹사를 선택하면 상세 영역에서 분류를 선택하고 `분류 ON/OFF`로 수집을 중지하거나 재개할 수 있습니다. `전체 ON/OFF`는 선택한 그룹사의 모든 분류에 적용됩니다.
- 상세 영역의 검색어를 클릭하거나 선택 후 Space를 누르면 해당 그룹사의 검색어만 ON/OFF 됩니다. OFF 검색어는 검색 요청과 기사 매칭에서 빠지고, 다른 ON 검색어와 일치하는 기사는 계속 표시됩니다. 검색어 하나는 ON으로 유지하며, 전체 중지는 `분류 OFF`를 사용합니다.
- `새 그룹사` 또는 그룹사 선택 후 `조건·분류 추가`로 편집 화면을 엽니다. 새 분류 이름과 검색어를 입력하고 `새 분류 추가`를 누른 뒤, 연결할 분류를 체크하고 `그룹사 등록 / 수정`으로 등록합니다. 예: `안전 사고` + `화재 | 산업재해`. 분류는 최대 12개이며 기본 분류와 같은 AND/OR 방식으로 수집됩니다.
- ON/OFF와 새 조건은 `저장하고 적용` 시 반영되고 재시작해도 유지됩니다. `취소`하면 변경을 적용하지 않습니다. 작은 창에서는 목록과 상세 영역이 세로로 배치되며 스크롤로 볼 수 있습니다.
- 예시 기사 제목을 입력하면 어느 분류에 포함되는지 확인할 수 있습니다.

검색 방식은 **(그룹사 이름 OR 약칭) AND (해당 분류의 검색어 OR 검색어)** 입니다.
공격 유형과 정부 대응은 각각 독립적으로 수집하므로 두 분류를 모두 포함할 필요가 없습니다.
뉴스 카드와 메인 필터에는 `한국전력 · 공격 유형`, `한국전력 · 개인정보위·정부 대응`처럼 표시됩니다.
두 조건에 모두 맞는 기사는 하나의 카드에 여러 태그가 붙습니다.

발전그룹사는 이름·약칭별 단순 검색으로 후보 기사를 수집하고, 그룹사·분류 검색어·제외어·확인 범위를 기사마다 검사합니다.
Google RSS가 긴 괄호/OR 검색식을 정상 응답 0건으로 반환하는 문제를 피하며, 같은 이름·약칭 요청은 분류 간 공유합니다.
기본 전체 등록은 22개 분류 조건, 공급자당 27개 고유 RSS 요청이며 네트워크 상태에 따라 수집 시간이 길어질 수 있습니다.
한 분류의 일부 요청이 실패하면 그 분류는 실패로 표시하고 기존 기사를 유지한 뒤 다음 주기에 재시도합니다.
해당 분류의 남은 요청은 생략하되, 다른 조건에서도 필요한 공유 요청은 계속 처리합니다.
검색 조건은 RSS 제목·설명에서 그룹사와 분류 검색어를 함께 확인합니다. 본문 요약은 검색 조건 판정 뒤 별도로 처리합니다.
`KPS`, `KDN`처럼 짧은 약칭은 다른 문구와 일치할 수 있으므로 필요하면 삭제하거나 제외어를 추가하세요.
약칭·분류·제외 조건을 바꾸면 해당 조건의 이전 기사 연결을 지우고 다시 수집합니다.
`취소`는 설정 초안을 적용하지 않습니다.

## RSS 요청 간격과 오류 복구

- Google RSS에는 브라우저 형식의 User-Agent, Accept, Accept-Language 헤더를 보냅니다.
- Google 요청은 한 번에 하나씩 전송하며, 요청 시작 사이에 최소 5초를 둡니다. 수동 확인과 다음 주기에도 간격이 유지됩니다.
- 자동 수집은 완료 후 최소 10분 간격입니다. 이전 설정이 10분보다 짧으면 불러올 때 10분으로 조정합니다.
- 429/503이면 해당 공급자의 남은 요청을 중단합니다. 첫 실패는 최소 5분, 반복 실패는 10분·20분·40분·60분으로 대기 시간을 늘립니다. Retry-After가 더 길면 그 시간을 따릅니다. 정상 RSS 또는 캐시를 검증한 304 응답을 받으면 실패 횟수를 초기화합니다.
- Google 대기 중에는 기존 Bing 대체 수집을 사용할 수 있습니다. 공급자별 대기 시간을 따로 관리하며, Google 요청은 대기 시간이 끝난 뒤 다음 수집 주기에 재시도합니다.
- 같은 주기의 동일한 검색 요청은 공유하며, 검색 조건·조회 기간·분류별 필터는 유지됩니다. 한 조건이 완료되면 그 결과부터 저장·표시합니다.
- ETag/Last-Modified 조건부 요청을 유지합니다. 304 응답에서만 검증된 이전 결과를 재사용하며 오류를 성공으로 처리하지 않습니다.
- 설정 변경이나 종료 시 대기 중인 요청을 취소합니다. 이미 전송한 요청은 응답 또는 제한 시간까지 기다립니다.

503만으로 봇 차단 여부를 확정할 수는 없습니다. 서버 장애나 네트워크 문제도 가능하며, 헤더와 요청 빈도를 조정해도 서버가 계속 503을 반환하면 Google 수집은 대기 상태로 유지됩니다.

## AND / OR / 제외 조건

`키워드 / 설정`의 `키워드 / 검색 조건` 탭에서 표시 이름과 검색 조건을 따로 설정합니다.
목록에서 기존 항목을 선택하면 해당 조건을 수정할 수 있습니다. `저장하고 적용`은 현재 편집 중인 조건도 반영합니다.
새로 만들려면 `새 조건`을 누릅니다. 표시 이름만 입력하면 이전과 동일한 문구 검색입니다.

| 검색 조건 | 의미 |
|---|---|
| `한전 AND 요금` | 한전과 요금 모두 포함 |
| `한전 OR 한국전력` | 둘 중 하나 이상 포함 |
| `한전 AND (전기 OR 요금)` | 한전 필수, 전기 또는 요금 포함 |
| `한전 NOT 주가` | 한전 포함, 주가 제외 |
| `한전 AND NOT (주가 OR 채용)` | 주가 또는 채용이 포함된 기사 제외 |
| `"한국 전력" AND 계약` | 한국 전력이라는 문구와 계약 포함 |

- AND/OR/NOT은 대소문자 구분 없이 사용 가능합니다. 우선순위는 NOT, AND, OR 순이며 괄호가 우선합니다.
- 검색어 사이의 공백은 AND로 해석합니다. 여러 단어를 하나의 문구로 찾으려면 큰따옴표로 묶습니다.
- 별도 `추가 제외어` 입력란은 쉼표로 구분합니다. 예: `주가, 채용 공고`. 모든 OR 분기에 적용됩니다.
- `제목만` 또는 `제목 + RSS 설명`을 선택합니다. 상세 조건은 검색 요청에 전달한 뒤 수집한 텍스트에서도 검사합니다.
- 포함 여부는 대소문자를 구분하지 않는 문구 포함으로 판단합니다. 영문 약어는 다른 영단어 내부와 일치하지 않도록 검사합니다. 기사 전문은 검사하지 않습니다.
- 미리보기에서 변환된 검색 조건을 확인하고, 예시 기사 제목을 입력해 포함/제외를 테스트할 수 있습니다. 테스트는 입력한 제목만 사용합니다.
- 조건 최대 500자, 제외어 최대 300자, 괄호/NOT 중첩 12단계, 변환 후 조건 조합 32개까지 지원합니다.
- 제외 조건만으로는 검색할 수 없습니다. 모든 OR 분기에 하나 이상의 포함 검색어가 필요합니다.
- 조건을 변경하면 해당 항목의 이전 기사 연결을 비우고 새 조건으로 다시 수집합니다. 다른 항목의 뉴스는 유지됩니다.
- 모니터링 설정은 별도 탭에 있고, 창 높이가 작아도 스크롤과 고정된 저장 버튼을 사용할 수 있습니다.

## 수집 정확도 검증

- 발전그룹사 조건은 그룹사 이름/약칭 중 하나 AND 켜 둔 분류 검색어 중 하나이며, 추가 제외어도 적용합니다.
- `한전KDN`, `한전KPS`, `한국전력기술`만 등장한 기사를 `한전` 또는 `한국전력`의 부분 문자열 때문에 한국전력 기사로 잘못 분류하지 않습니다.
- 사용자가 직접 별도 약칭을 등록한 경우에는 그 약칭을 인정합니다. 그룹사 이름에 붙는 `은`, `의` 등의 조사는 허용합니다.
- `APT`가 `CAPTIVE`에 포함됐다는 이유로 공격 기사로 판정하지 않습니다.
- RSS 설명에 함께 실린 다른 기사의 제목을 현재 기사의 검색 근거로 사용하지 않습니다.
- 미리보기에는 해당 기사의 그룹사 이름/약칭과 일치한 검색어를 함께 표시합니다.
- 서버 연결 실패는 검색 결과 0건과 구분해 안내합니다. 외부 서버의 오류를 코드 변경으로 해결했다고 표시하지 않습니다.
- `python audit_collection.py --all`은 현재 저장된 조건을 실제 Google/Bing RSS에서 읽기 전용으로 검사하고 `audit/latest.json`에 결과·오류·제공자를 저장합니다. 정상 네트워크 연결이 필요합니다.
- 2026-10-04 실측에서는 등록된 22개 조건이 오류 없이 완료됐고 Bing에서 한국전력 관련 기사 8건을 확인했습니다. 공격 유형 8건, 정부 대응 1건이며 중복 카드는 통합됩니다. 원문 응답 비교는 `audit/bing-*.xml`, 최종 검증 결과는 `audit/bing-fallback-live.json`에 있습니다.
- 웹 검색에서 발견된 기사도 제목/해당 RSS 설명에 등록 조건이 없거나 조회 기간 밖이면 표시하지 않습니다. 뉴스 제공자가 색인하지 않은 기사와 RSS 결과 수 제한으로 인한 누락 가능성은 남아 있습니다.
